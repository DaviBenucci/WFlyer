## Decisions

### Amend the active successor

Keep this change rather than create a second one: its existing geometry,
responsive, navigation and later motion boundary already matches the work.
Record prior achieved results separately from new-target acceptance. Reopen
5.1–5.5 and insert four implementation prerequisites before fresh validation and
5.6. Progress is 25/55, with all new-target work unchecked.

### Reuse existing semantic and projection owners

Extend existing `StoryChapterGeometry`, `ScorePathReviewChapterLayout`,
Projection's stable geometry/zone records and the positioning adapter. The
chapter manifest remains the semantic authority; do not build a second story
registry. Landmark entry is distinct from structural start/DOM center and from
Projection's musical `homeEntry` scenic handoff. Native vertical input is the
initial mapping in all classes, allowing lateral camera progression without a
new input engine. Native horizontal desktop input is optional, not required for
the first implementation package.

### Stage spatial metadata before geometry approval

Stage 1 needs minimal landmark/content/interaction/transition intervals and
camera mappings to construct and validate the target. Stage 3 still owns later
temporal draw/reveal/Assembly metadata after refreeze. Stage-1 validation can
inspect deterministic camera stations and the existing native-scroll adapter;
it does not implement new GSAP, Assembly or decorative reveal. Later motion
must validate traversal between already-approved spatial stations.

### Preserve safety, reconcile presentation

HGA-001A offset regularity, full ink, 12px clearance, event safety, zero invalid
intersections, deterministic music/hydration and interaction/accessibility
contracts remain. Old fan-specific simultaneous capacity and exact repair
shelves remain binding for the retained fan, not every sequential presentation.
Teaser-only vertical Projects is transitional; task 5.8 records its final
continuous-span disposition with required content and equivalent safety.
HGA-002's old margin plan is superseded; transition spans own continuity.

## Risks / Trade-offs

- Different physical span lengths can invalidate pixel restoration → restore
  landmark/content station and focused interaction via the new projection.
- Portrait or low-height layouts can hide content → prove reachable stations,
  readable reflow and native traversal; never shrink the entire composition.
- Form/keyboard changes can move a focused field → stable interaction region,
  bounded rebuild, retained values/focus and a reachable form/status surface.
- Existing tests may encode complete viewport fit → preserve raw failures and
  negative fixtures; replace only obsolete assertions with explicit equivalent
  reachability/focus coverage, retaining local ink and control safety.
- The dirty baseline includes uncommitted governance and product work → use the
  captured baseline and explicit delta staging; skip commit if isolation is
  ambiguous. No cleanup, reset or unrelated staging.

## Migration and validation

Follow [tasks](tasks.md) and the [bounded package](continuous-story-implementation-package.md).
First implement only task 5.7 on a subsequent implementation run. Remaining
slices proceed in dependency order; new Projects disposition and meaningful
span dimensions are measured implementation outputs within the canonical rules.
New fundamental conflicts return to architecture governance.

Validate pure mapping and geometry first, affected browser cases next, then a
stable full representative matrix under canonical §13. Preserve both owner
low-height profiles and their DPR. No prior capture substitutes for new-target
review. Human Geometry Approval, refreeze, Assembly, GSAP and public release
remain separate pending gates. Failure exposes the same semantic document.
Rollback preserves the transitional snapshot and independent dirty work; no
historical artifact or frozen Phase-9 evidence is rewritten.

Governance validation uses strict OpenSpec, registry/traceability/reference and
structured-manifest checks plus scoped diff checks and baseline hashes. No
product tests or new browser captures are required for this documentation pass.
Graphify was used for navigation; no AST changed and no regeneration is required.
