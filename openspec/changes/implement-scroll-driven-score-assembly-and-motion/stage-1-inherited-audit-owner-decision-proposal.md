## A. Application-access reservation architecture

**Recommendation: B as ownership, a derived A as its payload, and C only for
existing geometry transport.** Use one narrow, versioned Access scene-envelope
contract outside Projection. Its deterministic maximum is a function of the
approved content/release revision, layout/typography profile and available
inline size. Reuse `contentRect` and section sizing where applicable; do not
build a generic measurement framework or duplicate the form in Projection.

| Criterion | A: derived fixed envelope per supported layout profile | B: scene-owned stable envelope metadata | C: reuse existing reservation mechanism alone |
| --- | --- | --- | --- |
| Determinism | Good if derived, versioned and conservative over the full profile. | Good with a pure resolver and explicit stable inputs. | Existing numeric rectangles are deterministic; present Access numbers are insufficient. |
| SSR/hydration | Same server/client value; cannot choose a browser width during server render. | Same contract revision and hydration baseline on server/first client. | Preserve existing baseline and input serialization. |
| First client | No measurement correction required; existing post-hydration responsive transition remains. | Same; update profile only through the existing responsive lifecycle. | Existing runtime scene measurements alone are not an all-state reservation. |
| DOM dependency | None in production; offline derivation/verification needed. | None added for Access; DOM is evidence, not the source of its reserve. | Numeric transport is reusable; live current-state rectangle measurement is not enough. |
| Invalidation | Content, metrics or layout-profile revision. | Explicit version plus existing meaningful resize/mode lifecycle. | Existing lifecycle can transport input; it does not establish state-complete maxima. |
| Ordinary interaction | Fixed reserve across input, error, verification and submission. | Same; no status-driven Projection rebuild. | Measuring the current form after every status would violate this property. |
| Layout shift | May leave spare space; prevents state-driven outer movement. | Same with tighter profile-specific derivation. | Current fixed bounds overflow; ad hoc measurement can shift/loop. |
| Responsive behavior | A single universal constant wastes space and may miss wrapping; supported intervals need proof. | Width/profile function can model real CSS regimes without viewport exceptions. | Existing per-chapter sizing lacks a complete PRELAUNCH envelope. |
| Testability | State maximum and derivation fixtures. | Same plus input version, SSR and lifecycle assertions. | Existing output validators stay useful; mechanism alone does not repair the contract. |
| Maintenance | Smallest payload, but detached constants risk drift. | One scene-specific contract tied to source/copy/style changes; no generic registry required. | Lowest wiring cost, but an unexplained replacement number repeats the root cause. |
| PRELAUNCH to LIVE | Separate derived revision after release approval. | Explicit release discriminant and separately approved LIVE contract. | Existing release branch remains; reservation must change deliberately with it. |
| Feedback-loop risk | None if pure. | None if pure and status-independent. | Reusing arbitrary measured `sceneMeasurements` as the maximum risks feedback/rebuilds. |
| Scope | Local reservation plus proved local support. | Same, with a narrow input adapter outside Projection. | Reuse data structures only; generic sizing/measurement redesign excluded. |

## C. Taxonomy and causal classification

**Recommendation:** keep causal class, raw validation, runtime disposition and
stage disposition as separate fields.

| Class/result | Required evidence | Default stage effect |
| --- | --- | --- |
| CURRENT_REGRESSION | New or materially worse behavior against equivalent frozen input, attributable to a current delta. Record whether successor or another dirty change owns it. | BLOCK_STAGE |
| INHERITED_CRITICAL | Equivalent inherited behavior violates a mandatory invariant or materially compromises supported functionality/accessibility/security. | BLOCK_STAGE |
| INHERITED_NONBLOCKING | Equivalent, not worsened, noncritical, no mandatory invariant violation or material functional/accessibility/security loss. | BLOCK pending explicit individual owner DEFER; no automatic exemption. |
| VALIDATION_PIPELINE_DEFECT | Causal evidence of incorrect measurement, lifecycle, readiness, construction or assertion infrastructure. | Block affected evidence qualification; recommend pipeline correction, not product geometry changes. |
| UNCLASSIFIED / NEEDS_REVIEW | Missing/inequivalent input, incomplete replay, unexplained discrepancy or uncertain severity. | BLOCK qualification; continue independent audit observations. |
| PASS | The declared observation's validator passed on its actual input. | Only that observation is clear; not whole-stage approval. |

`SAFE_FALLBACK` is a separate runtime result, never a root class or PASS alias.
An observed overflow establishes the acceptance failure; it does not by itself
prove that a public user lost data or that every route is unusable. Record actual
clip/reachability/focus/CTA impact. Access remains blocking under the existing
required zero-overflow contract even while broader impact is being measured.

**Alternative/trade-off:** classifying by screenshot/test count is easier but
repeats the current loop and inflates roots. A single severity label loses
causality and fallback distinctions. **Scope/owners:** audit executor proposes
classes with evidence; owner ratifies severity/disposition in the batch.
**Acceptance/impact/invariants:** every failed observation maps to a root or an
explicit unresolved item; no inherited label from a historical PASS alone, no
pipeline label just because an assertion fails, and no product repair in audit.

**Recommendation:** block all current regressions, inherited critical findings,
mandatory-invariant failures, materially broken accessibility/functionality,
clipped/unreachable critical content or controls, navigation/CTA failure,
security/data-integrity impact, missing required safe fallback, and unresolved
or incomplete required evidence. All required invariant checks remain enabled.

Mandatory protections include full visible staff/event ink, global zero center
and staff intersections, existing tangent/event-safe rules, 12px physical
clearance, three Projects visits/NON-ASSEMBLY, Composer fingerprints/semantics,
ADR-046 equality, required content/overflow/function/a11y checks and lifecycle
cleanup. The current Access failure cannot be deferred through this proposal.

Only consider DEFER when **all** are true: evidenced inherited equivalence;
no worsening; noncritical; no material functionality/a11y loss; no security or
data-integrity impact; no mandatory invariant failure; explicit finding-specific
owner approval; enabled detecting validator and visible raw result; named
remediation owner, review point and measurable baseline. Unknown evidence is
not equivalence. Expired approval, new occurrence outside its approved coverage,
worsened metric/impact or a new invariant failure reblocks the finding.

The gate reports separately:

- `BLOCKED`: any blocking or unresolved required item/coverage gap.
- `ELIGIBLE_WITH_APPROVED_DEFERRALS`: mandatory checks pass and only approved
  noncritical supplementary findings remain, all within their recorded bounds.
- `ELIGIBLE`: mandatory checks and complete declared coverage are clear.

Neither eligible result marks Human Geometry Approval or authorizes Stage 2.
Raw validator assertions, failures and exit status remain intact. A future
disposition aggregator may recognize approved debt, but must never publish
`ALL_TESTS_PASS` for a failing raw run. No existing mandatory test can be silently
reclassified as supplementary. If a contemplated defer requires waiving an
existing must-pass test/invariant, it is **outside this package** and remains
blocked; AGENTS phase discipline and canonical precedence are not overridden.
This makes defer useful for evidenced ancillary quality debt, not a loophole
for current geometric/form acceptance failures.

**Alternative/trade-off:** block every supplementary cosmetic inherited finding
too; simpler reporting, greater delay. Automatic defer or mandatory-invariant
waivers are not recommended options. **Scope/owners:** successor-stage gate
interpretation; owner alone approves per-finding defer; QA/executor evaluates
equivalence without editing thresholds. **Acceptance/impact:** exercise gate
logic later with worsening, expired/missing approval, incomplete evidence,
pipeline failure and known nonblocking debt. This run only proposes the rules.

## F. Safe fallback and invalid candidates

**Recommendation:** report candidate validity, actual runtime mode and stage
disposition independently. A deterministic supported fallback can protect users
while a horizontal candidate remains rejected. `INSUFFICIENT_CAPACITY` is not
`PASS`; lack of trustworthy inputs is not sufficient-capacity evidence.

Preserve ASM-PC-001's approved capacity-selected whole-story fallback and its
strict predicate. Registered negative fixtures stay negative. At least the
appropriate horizontal candidate required by 013/014 must qualify; universal
fallback must not conceal failure. Pure horizontal 1100x640 geometry checks,
all visible-segment intersection guards and all complete-capacity checks remain.

A test correctly recognizing an expected capacity rejection can PASS **that
classification assertion** without making the candidate PASS. A supported
insufficient-capacity outcome is not automatically a new defect. Conversely,
fallback does not waive a failed mandatory geometric invariant, missing
horizontal-qualification obligation or defect requiring owner disposition.

**Alternative/trade-off:** force enhancement everywhere; contradicts existing
capacity authority and reduces safety. Treat fallback as validator success;
conceals failures and is forbidden. **Scope/owners:** runtime chooses supported
mode under existing policy; validators report candidate facts; owner controls
disposition. **Acceptance/impact:** future evidence includes all three values
and rejected-candidate diagnostics; do not change the candidate predicate or
runtime fallback algorithm in this governance run.
